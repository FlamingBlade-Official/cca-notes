这样可以把「经过的天数」直接转换为从第 1 天（1 月 1 日）开始累积的日序号。之后所有的整除和取余都可以自然地对应到年月日，不再需要单独处理"中午 12 点"这个边界。

## Hint 2

<details>
<summary>历史上有两次历法切换：<strong>儒略历</strong>四年一闰；<strong>格里高利历</strong>在 1582 年 10 月 4 日之后跳过 10 天，并且闰年规则改为"被 4 整除但不被 100 整除，或被 400 整除"。如何把日期分成几个区间来分段处理？</summary>

我们把日期分成三段：

1. **公元前（BC）**：从第 1 天到 $4712 \times 365 + (4712/4) \times 1 + 366$ 天（即覆盖 4713 BC ~ 1 BC 的所有天数）。此区间用**儒略历**计算，年份输出时带上 `BC` 后缀。
2. **公元 1 年 ~ 1582 年 10 月 4 日**：儒略历，按四年一闰正常计算。
3. **1582 年 10 月 15 日及以后**：进入格里高利历。需要补偿缺失的 10 天，并扣除儒略历多算的闰年天数（被 100 整除但不被 400 整除的年份在格里高利历中不是闰年）。

分段判断 `date` 落在哪一段，再调用对应的 `getans()` 即可。

</details>

## Hint 3

<details>
<summary>如果输入的 $d$ 高达 $10^9$，对应年份可以到几百万甚至上千万。逐年循环会超时。儒略历和格里高利历各自的年份有什么<strong>循环规律</strong>可以利用？</summary>

- **儒略历**：每 **4 年**是一个完整循环，包含 1 个闰年 + 3 个平年，共 $366 + 365 \times 3 = 1461$ 天。
- **格里高利历**：每 **400 年**是一个完整大循环，其中闰年个数为 $400/4 - 400/100 + 400/400 = 97$，共 $365 \times 400 + 97 = 146097$ 天。

算法：
- 用 `(n-1) / 周期天数` 快速跳过整周期，`n` 减去对应天数。
- 在剩余不足一个周期的年份内逐年判断，最后逐月扣除，得到精确日期。

这样查询一次仅需 $O(\text{周期内年数})$ 即 $O(4)$ 或 $O(400)$ 的常数级别操作。

</details>

## Hint 4

<details>
<summary>我们假设有一个函数 <code>getans(date, op)</code> 能在 $op = 0$ 时返回儒略日期，$op = 1$ 时返回格里高利日期。但从儒略历切换到格里高利历时，儒略历把「被 100 整除但不被 400 整除」的年份也当作了闰年——这些"多出来的 2 月 29 日"在格里高利历中是不存在的。并且格里高利历还凭空缺少了 10 天。我们如何处理？</summary>

从公元 1 年到 1582 年，被 100 整除的年份数 = $1582 / 100 = 15$，被 400 整除的年份数 = $1582 / 400 = 3$。所以儒略历比格里高利历多算了 $15 - 3 = 12$ 个闰年。

在进入格里高利历区间后，代码执行：

```cpp
date += 10;                       // 补回缺失的 10 天（1582.10.5 ~ 10.14）
date -= 1582 / 100 - 1582 / 400;  // 扣除格里高利历比儒略历少算的闰年天数（12 天）
```

这样 `date` 就与格里高利历的实际日数对齐，可以放心调用 `getans(date, 1)` 来计算。

</details>

## Solution

<details>
<summary>查看完整思路与代码解析</summary>

### 1. 整体流程

```cpp
void solve() {
    cin >> date; date++;  // 将"经过天数"转为"日序号"
```

然后按顺序判断：

#### 第一段：公元前

```cpp
if (date <= (4712 / 4) * (365 * 4 + 1) + 366) {
    // BC
    Date ans = getans(date, 0);
    cout << ans.day << " " << ans.month << " "
         << 4713 - ans.year << " BC" << endl;
    return;
}
```

- 公元前总天数 = $4712 \times 365 + (4712/4) \times 1 + 366$（即 4713 BC ~ 1 BC，其中第一年 4713 BC 是闰年 366 天，此后每 4 年一个闰年）。
- 用儒略历 `getans(date, 0)` 得到年份（从 year 0 起算，year 0 = 4713 BC），实际年份 = $4713 - \text{year}$，输出带 `BC`。

#### 第二段：公元 1582.10.4 及以前

```cpp
date -= (4712 / 4) * (365 * 4 + 1) + 366;  // 减去公元前天数

int date_of_gregorian = 1581 * 365 + (1581 / 4);
for (int i = 1; i <= 9; ++i) date_of_gregorian += month[i];
date_of_gregorian += 4;  // 1582.10.04 是这一段的最后一天

if (date <= date_of_gregorian) {
    Date ans = getans(date + 366, 0);  // +366 因为从公元 0 年虚拟起点开始
    cout << ans.day << " " << ans.month << " " << ans.year << endl;
    return;
}
```

- `date_of_gregorian` 计算从公元 1 年 1 月 1 日到 1582 年 10 月 4 日的总天数。
- `getans` 内部是从 year 0 开始算的，所以传入时 `+366`（公元 0 年在儒略历中是虚拟闰年，366 天）。

#### 第三段：格里高利历

```cpp
date += 10;                       // 补回缺失的十天
date -= 1582 / 100 - 1582 / 400;  // 扣除儒略历多算的闰年

Date ans = getans(date + 366, 1);
cout << ans.day << " " << ans.month << " " << ans.year << endl;
```

### 2. `getans(n, op)` 函数

#### 儒略历 (`op == 0`)

```cpp
ll p4 = (n - 1) / (365 * 4 + 1);   // 整 4 年周期
n -= p4 * (365 * 4 + 1);

for (int i = 0; i <= 4; ++i) {
    if (n > year[i]) { n -= year[i]; continue; }
    // 周期第一年是闰年
    if (i == 0) month[1] = 29; else month[1] = 28;

    for (int j = 0; j <= 11; ++j) {
        if (n > month[j]) n -= month[j];
        else return (Date){p4 * 4 + i, j + 1, n};
    }
}
```

- 每 4 年 1461 天为一个块快速跳过。
- 剩余在不足 4 年内逐年后逐月处理。

#### 格里高利历 (`op == 1`)

```cpp
ll p400 = (n - 1) / (365 * 400 + 97);  // 整 400 年周期
n -= p400 * (365 * 400 + 97);

for (int i = 0; i < 400; ++i) {
    if (i % 400 == 0 || (i % 4 == 0 && i % 100 != 0))
        month[1] = 29;
    else month[1] = 28;

    for (int j = 0; j < 12; ++j) {
        if (n > month[j]) n -= month[j];
        else return (Date){p400 * 400 + i, j + 1, n};
    }
}
```

- 每 400 年 146097 天为一个块快速跳过。
- 剩余在不足 400 年内逐年处理，闰年判断按格里高利规则。

### 3. 关键边界一览

| 边界 | 处理方式 |
|------|----------|
| 输入 $d=0$ 代表起始日 | `date = d+1`，自然对应 1 月 1 日 |
| 公元前第一年（4713 BC）是闰年 | `year[0] = 366`，且 `getans` 从 year 0（闰年）开始 |
| 公元 0 年（虚拟） | `getans(date + 366, 0)`，用 366 天跳过虚拟年 |
| 1582.10.5~10.14 不存在 | `date += 10` 跳过 |
| 格里高利历比儒略历少算的闰年 | `date -= 12` 扣除（公元 1~1582 年间共 12 个） |

整个模拟通过**分段判断 + 循环压缩**，将 $O(\text{年份})$ 的复杂度降低到 $O(1)$ 常数查询。

</details>

## 思考题

**Q1.** 为什么 `getans` 的参数 `n` 必须保证 $n \ge 1$？如果传入 $n = 0$ 会发生什么？

<details>
<summary>点击查看参考答案</summary>

`(n-1) / 周期天数` 在 $n = 0$ 时分子为 $-1$，C++ 中整数除法向零取整得到 $0$ 或 $-1$（取决于实现），导致跳过错误的周期数，且后续 `n -= ...` 和循环逻辑将产生不可预期的结果。因此 $n$ 至少为 $1$。

</details>

**Q2.** 格里高利历的 400 年周期内有 97 个闰年，这个数字是怎么算出来的？

<details>
<summary>点击查看参考答案</summary>

400 年内能被 4 整除的有 $400/4 = 100$ 个；从中去掉能被 100 整除的 $400/100 = 4$ 个；再加回能被 400 整除的 $400/400 = 1$ 个。$100 - 4 + 1 = 97$。

</details>

**Q3.** 如果输入的 $d$ 恰好对应 1582 年 10 月 5 日到 10 月 14 日这些"不存在"的日期，题目保证不会出现这样的输入吗？如果出现了，你的程序会输出什么？

<details>
<summary>点击查看参考答案</summary>

题目保证所有查询的日期都是**合法存在**的，所以不会出现 1582.10.5~10.14 这些日期。如果真的出现了，程序的 `date += 10` 会让它跳入格里高利历的正常区间，输出一个"看起来合理但实际错误"的日期——这恰好说明题目约束的重要性。

</details>
