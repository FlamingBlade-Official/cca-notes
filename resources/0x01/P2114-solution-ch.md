# 题解：P2114 [NOI2014] 起床困难综合症

> 源代码：`P2114.cpp`

---

## Hint 1

<details>
<summary>对于每一个运算，他们的每一个二进制位是独立的吗？为什么？</summary>
</details>

<details>
<summary>答案</summary>

是的。  
`AND`、`OR`、`XOR` 这三种运算在**二进制下都是按位操作**，位与位之间不存在进位或借位。  
因此，我们可以把每一扇门的作用拆成对 $30$ 个二进制位分别的影响，互不干扰。

</details>

---

## Hint 2

<details>
<summary>每一位是独立的，那么我们为了打到最大的攻击伤害，可以做什么？</summary>
</details>

<details>
<summary>答案</summary>

**从高位到低位贪心**。  
因为高位上的 $1$ 贡献的伤害远大于所有低位贡献的总和（$2^i > \sum_{j=0}^{i-1} 2^j$），我们应当优先尝试让高位变成 $1$，并且尽可能不消耗 $m$ 的限额。  
具体做法是：对每个二进制位 $i$，分别让这一位为 $0$ 和为 $1$ 跑一遍所有门，看最终这一位会变成什么。然后根据结果决定初始值这一位填 $0$ 还是 $1$。

</details>

## Hint 3

<details>
<summary>假如说我们想在第 $i$ 位打到 $2^i$ 的伤害，如何知道哪些数是允许的？</summary>
</details>

<details>
<summary>答案</summary>

我们先计算两个"探针值"：  
- `ans0 = 0`：初始攻击力在第 $i$ 位为 $0$  
- `ans1 = 1`：初始攻击力在第 $i$ 位为 $1$  

把这两个值分别通过所有 $n$ 扇门（只关注第 $i$ 位的结果），得到最终这一位的输出 `bit0` 和 `bit1`。  
- 如果 `bit0 == 1`，说明我们什么都不用付出，第 $i$ 位就能得到 $1$，那就果断选 $0$。  
- 如果 `bit0 == 0` 而 `bit1 == 1`，且当前已经花费的初始值加上 $2^i$ 仍然 $\le m$，则可以选 $1$，并让已花费值增加 $2^i$。  
- 否则这一位只能为 $0$。

这样我们就知道哪些初始值能做到「花费尽量少、收益尽量高」。

</details>

## Hint 4

<details>
<summary>如何高效计算出每个二进制位经过所有门后的最终值？</summary>
</details>

<details>
<summary>答案</summary>

我们可以从高位到低位（或反过来）统一处理：  
对于第 $i$ 位，设 $t=0$ 和 $t=1$ 两个数，它们的其他位均为 $0$，然后依次经过 $n$ 扇门。  
也可以直接在遍历门的时候模拟位运算：代码中从后往前循环门，但因为是按位独立，正序倒序结果一致。

简化写法：预先用两个变量 $val0 = 0$ 和 $val1 = (1<<30)-1$ 一次性跑完所有门，得到每一位的变换结果。  
`(val0>>i)&1` 就是输入 $0$ 时的输出，`(val1>>i)&1` 是输入 $1$ 时的输出。  
但注意 $val1$ 的高位初始为 $1$ 可能会超出 $m$ 的限制判断，所以仍需要按位贪心并维护花费。

</details>

## Hint 5

<details>
<summary>贪心时，初始攻击力不能超过 $m$，具体怎么控制？</summary>
</details>

<details>
<summary>答案</summary>

维护一个变量 `cur = 0` 表示当前已经确定的初始值大小。  
从高到低位枚举：  
- 若 $0$ 就能得到 $1$，直接选 $0$（不增加 `cur`）。  
- 否则若 $1$ 能得到 $1$ 且 `cur + (1<<i) <= m`，则选 $1$，`cur += (1<<i)`。  
- 其余情况选 $0$。

最终答案就是所有被选出的位贡献之和。

</details>

## Hint 6

<details>
<summary>为什么从高位开始贪心是正确的？会不会因为低位选择而影响高位？</summary>
</details>

<details>
<summary>答案</summary>

因为高位决策独立于低位。  
即便我们为了凑低位而修改了高位，一旦高位变成 $0$，损失的伤害永远无法由低位弥补（$2^i > \sum_{j=0}^{i-1}2^j$）。  
因此，优先确保高位为 $1$ 并且尽量不消耗 $m$ 是最优策略。这就是**位运算贪心的常见证明**。

</details>

## Solution

<details>
<summary>查看完整思路与代码解析</summary>

### 1. 读入与存储

```cpp
int n, m;
int a[N], b[N];  // a: 操作类型, b: 参数
cin >> n >> m;
for (int i = 1; i <= n; ++i) {
    string s;
    cin >> s >> b[i];
    if (s == "AND") a[i] = 0;
    if (s == "OR")  a[i] = 1;
    if (s == "XOR") a[i] = 2;
}
```

### 2. 按位枚举 + 模拟

```cpp
int ans = 0;      // 初始攻击力累计值
int damage = 0;   // 最终伤害
for (int i = 30; i >= 0; --i) {
    int ans0 = 0;   // 这一位填 0 的初态
    int ans1 = 1;   // 这一位填 1 的初态
    for (int j = n; j >= 1; --j) {   // 遍历所有门
        int op = (b[j] >> i) & 1;    // 参数在第 i 位的值
        if (a[j] == 0) {      // AND
            if (op == 0) ans1 = ans0;   // 1 & 0 = 0，和 ans0 相同
        } else if (a[j] == 1) { // OR
            if (op == 1) ans0 = ans1;   // 0 | 1 = 1，和 ans1 相同
        } else if (a[j] == 2) { // XOR
            if (op == 1) swap(ans0, ans1); // 0 ^ 1 = 1, 1 ^ 1 = 0
        }
    }
    if (ans0) {                     // 0 能变 1
        damage += (1 << i);
    } else if (ans1 && ans + (1 << i) <= m) { // 1 能变 1 且不超限
        ans += (1 << i);
        damage += (1 << i);
    }
}
```

注意：循环 `j` 从 `n` 到 `1` 仅表示遍历顺序，不影响按位独立的最终结果。也可以正序。

### 3. 输出

```cpp
cout << damage << endl;
```

时间复杂度：$O(31 \cdot n) \approx O(n)$，轻松通过。

</details>

## 思考题

<details>
<summary>Q1. 如果运算不仅有 `AND,OR,XOR`，还加入了 `NOT`（只有操作数，没有参数），按位独立的性质还成立吗？贪心策略是否需要调整？</summary>
</details>

<details>
<summary>参考答案</summary>

`NOT` 同样是按位取反，一位的输入只影响该位的输出，因此独立性依然成立。贪心策略不变，只需要在模拟时增加 `NOT` 的处理：`ans = !ans`。

</details>

<details>
<summary>Q2. 为什么代码中 `ans1 = ans0` 这样的赋值能够正确模拟 `AND 0`？这背后的逻辑是什么？</summary>
</details>

<details>
<summary>参考答案</summary>

当参数在该位为 $0$ 时，`AND 0` 一定得到 $0$，**无论输入是 $0$ 还是 $1$**。  
因此 `ans0`（输入 $0$ 的结果）和 `ans1`（输入 $1$ 的结果）此时都等于最终为 $0$ 时对应的那个状态。代码中用 `ans1 = ans0` 是把两者统一为原来输入 $0$ 的结果（因为 `ans0` 刚好就是经过 `AND 0` 后的值——原来输入 $0$ 经 `AND 0` 得 $0$，输入 $1$ 也得 $0$）。  
类似地，`OR 1` 时 `ans0 = ans1` 也是同样的道理。

</details>

<details>
<summary>Q3. 如果 $m$ 很大（比如 $10^{18}$），但门的参数范围也相应扩大，算法是否需要修改？本题的 $m=10^9$ 下为何只枚举到 $30$ 位？</summary>
</details>

<details>
<summary>参考答案</summary>

题目中参数 $t$ 以及 $m$ 都不超过 $10^9$，$10^9 < 2^{30}$，因此 $30$ 位（$0\sim 30$）足够覆盖所有可能。如果 $m$ 更大，只需枚举更多位（如 $0\sim 60$），算法框架不变。

</details>

## 启示

<details>
<summary>从本题可以学到什么？</summary>
</details>

<details>
<summary>答案</summary>

- **位运算独立性**：`AND/OR/XOR` 等按位操作天然可以让问题降维，把一个大整数问题分解为若干独立的布尔问题。
- **高位优先贪心**：在二进制权值差距极大的场景下，从高位贪心既能保证最优解，又能大幅降低复杂度。
- **模拟预处理**：分别跑 $0$ 和 $1$ 的"探针"，就可以快速得知每一位的选择后果，无需暴力枚举所有初始值。

</details>
