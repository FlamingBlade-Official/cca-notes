# 题解：P2114 [NOI2014] 起床困难综合症

> 源代码：`P2114.cpp`

---

## Hint 1

<details>
<summary>Hint 1 问题</summary>

对于每一个运算，他们的每一个二进制位是独立的吗？为什么？

</details>

<details>
<summary>Hint 1 答案</summary>

是的。

`AND`、`OR`、`XOR` 这三种运算在**二进制下都是按位操作**，位与位之间不存在进位或借位。

因此，我们可以把每一扇门的作用拆成对 30 个二进制位分别的影响，互不干扰。

</details>

---

## Hint 2

<details>
<summary>Hint 2 问题</summary>

每一位是独立的，那么我们为了打到最大的攻击伤害，可以做什么？

</details>

<details>
<summary>Hint 2 答案</summary>

**从高位到低位贪心**。

因为高位上的 1 贡献的伤害远大于所有低位贡献的总和（2^i > Σ 2^j, j = 0...i-1），我们应当优先尝试让高位变成 1，并且尽可能不消耗 m 的限额。

具体做法是：对每个二进制位 i，分别让这一位为 0 和为 1 跑一遍所有门，看最终这一位会变成什么。然后根据结果决定初始值这一位填 0 还是 1。

</details>

## Hint 3

<details>
<summary>Hint 3 问题</summary>

假如说我们想在第 i 位打到 2^i 的伤害，如何知道哪些数是允许的？

</details>

<details>
<summary>Hint 3 答案</summary>

我们先计算两个"探针值"：

- `ans0 = 0`：初始攻击力在第 i 位为 0
- `ans1 = 1`：初始攻击力在第 i 位为 1

把这两个值分别通过所有 n 扇门（只关注第 i 位的结果），得到最终这一位的输出 `bit0` 和 `bit1`。

- 如果 `bit0 == 1`，说明我们什么都不用付出，第 i 位就能得到 1，那就果断选 0。
- 如果 `bit0 == 0` 而 `bit1 == 1`，且当前已经花费的初始值加上 2^i 仍然 ≤ m，则可以选 1，并让已花费值增加 2^i。
- 否则这一位只能为 0。

这样我们就知道哪些初始值能做到「花费尽量少、收益尽量高」。

</details>

## Hint 4

<details>
<summary>Hint 4 问题</summary>

如何高效计算出每个二进制位经过所有门后的最终值？

</details>

<details>
<summary>Hint 4 答案</summary>

我们可以从高位到低位（或反过来）统一处理：

对于第 i 位，设 t=0 和 t=1 两个数，它们的其他位均为 0，然后依次经过 n 扇门。

也可以直接在遍历门的时候模拟位运算：代码中从后往前循环门，但因为是按位独立，正序倒序结果一致。

简化写法：预先用两个变量 `val0 = 0` 和 `val1 = (1<<30)-1` 一次性跑完所有门，得到每一位的变换结果。

`(val0>>i)&1` 就是输入 0 时的输出，`(val1>>i)&1` 是输入 1 时的输出。

但注意 val1 的高位初始为 1 可能会超出 m 的限制判断，所以仍需要按位贪心并维护花费。

</details>

## Hint 5

<details>
<summary>Hint 5 问题</summary>

贪心时，初始攻击力不能超过 m，具体怎么控制？

</details>

<details>
<summary>Hint 5 答案</summary>

维护一个变量 `cur = 0` 表示当前已经确定的初始值大小。

从高到低位枚举：

- 若 0 就能得到 1，直接选 0（不增加 `cur`）。
- 否则若 1 能得到 1 且 `cur + (1<<i) <= m`，则选 1，`cur += (1<<i)`。
- 其余情况选 0。

最终答案就是所有被选出的位贡献之和。

</details>

## Hint 6

<details>
<summary>Hint 6 问题</summary>

为什么从高位开始贪心是正确的？会不会因为低位选择而影响高位？

</details>

<details>
<summary>Hint 6 答案</summary>

因为高位决策独立于低位。

即便我们为了凑低位而修改了高位，一旦高位变成 0，损失的伤害永远无法由低位弥补（2^i > Σ 2^j, j = 0...i-1）。

因此，优先确保高位为 1 并且尽量不消耗 m 是最优策略。这就是**位运算贪心的常见证明**。

</details>

## Solution

<details>
<summary>查看完整思路与代码解析</summary>

### 核心思想

本题的两大关键：

1. **位运算独立性**：AND、OR、XOR 都是按位操作，位与位之间互不影响。因此我们可以把「一个 30 位的整数经过 n 扇门」拆成「30 个独立的布尔值分别经过 n 扇门」。

2. **高位优先贪心**：二进制下，第 i 位的权重 2^i 大于所有低位权重之和。所以我们从最高位（第 30 位）到最低位（第 0 位）依次决策：优先让高位得 1，且尽量不消耗 m 的限额（即能选 0 就不选 1）。

### 1. 读入与存储

```cpp
int n, m;
int a[N], b[N];  // a: 操作类型, b: 参数
cin >> n >> m;
for (int i = 1; i <= n; ++i) {
    string s;
    cin >> s >> b[i];
    if (s == "AND") a[i] = 0;
    if (s == "OR")  a[i] = 1;
    if (s == "XOR") a[i] = 2;
}
```

用数组 `a[i]` 存储第 i 扇门的类型（0=AND, 1=OR, 2=XOR），`b[i]` 存储操作参数 t。

### 2. 按位枚举 + 模拟

```cpp
int ans = 0;      // 已确定的初始攻击力（累计值）
int damage = 0;   // 最终伤害
for (int i = 30; i >= 0; --i) {
    int ans0 = 0;   // 这一位填 0 的初态
    int ans1 = 1;   // 这一位填 1 的初态
    for (int j = n; j >= 1; --j) {   // 遍历所有门
        int op = (b[j] >> i) & 1;    // 参数在第 i 位的值
        if (a[j] == 0) {      // AND
            if (op == 0) ans1 = ans0;   // 1 & 0 = 0，和 ans0 相同
        } else if (a[j] == 1) { // OR
            if (op == 1) ans0 = ans1;   // 0 | 1 = 1，和 ans1 相同
        } else if (a[j] == 2) { // XOR
            if (op == 1) swap(ans0, ans1); // 0 ^ 1 = 1, 1 ^ 1 = 0
        }
    }
    if (ans0) {                     // 0 能变 1
        damage += (1 << i);
    } else if (ans1 && ans + (1 << i) <= m) { // 1 能变 1 且不超限
        ans += (1 << i);
        damage += (1 << i);
    }
}
```

**逐位模拟的逻辑**：

对于第 i 位，我们维护两个值 `ans0` 和 `ans1`，分别表示「这一位初始为 0 / 1 时，经过当前已处理的门后的值」。初始时 `ans0 = 0`, `ans1 = 1`。

然后依次经过每一扇门，根据门的类型和参数在该位的值 `op` 来更新：

- **AND**：如果 `op == 1`，则 `ans0` 和 `ans1` 都不变（因为 `x & 1 = x`）；如果 `op == 0`，则无论输入是什么，结果都是 0，所以 `ans1 = ans0`（两者都变成原来 `ans0` 的值，即都为 0）。
- **OR**：如果 `op == 0`，则不变；如果 `op == 1`，则 `ans0 = ans1`（两者都变成原来 `ans1` 的值，即都为 1）。
- **XOR**：如果 `op == 1`，则翻转——`swap(ans0, ans1)`；如果 `op == 0`，则不变。

遍历完所有门后，`ans0` 和 `ans1` 就是这一位最终的结果。然后贪心：

- 若 `ans0 == 1`：填 0 就能得到 1，最好，直接计入伤害。
- 否则若 `ans1 == 1` 且不超 m：填 1 能得到 1，消耗 m，计入伤害。
- 否则：只能填 0，得 0，无贡献。

注意：循环 `j` 从 `n` 到 `1` 仅表示遍历顺序，不影响按位独立的最终结果。也可以正序。

### 3. 输出

```cpp
cout << damage << endl;
```

时间复杂度：O(31 · n) ≈ O(n)，轻松通过。

</details>

## 思考题

<details>
<summary>Q1 问题</summary>

如果运算不仅有 AND, OR, XOR，还加入了 NOT（只有操作数，没有参数），按位独立的性质还成立吗？贪心策略是否需要调整？

</details>

<details>
<summary>Q1 答案</summary>

NOT 同样是按位取反，一位的输入只影响该位的输出，因此独立性依然成立。贪心策略不变，只需要在模拟时增加 NOT 的处理：`ans = !ans`。

</details>

<details>
<summary>Q2 问题</summary>

为什么代码中 `ans1 = ans0` 这样的赋值能够正确模拟 AND 0？这背后的逻辑是什么？

</details>

<details>
<summary>Q2 答案</summary>

当参数在该位为 0 时，`AND 0` 一定得到 0，**无论输入是 0 还是 1**。

因此 `ans0`（输入 0 的结果）和 `ans1`（输入 1 的结果）此时都等于最终为 0 时对应的那个状态。代码中用 `ans1 = ans0` 是把两者统一为原来输入 0 的结果（因为 `ans0` 刚好就是经过 AND 0 后的值——原来输入 0 经 AND 0 得 0，输入 1 也得 0）。

类似地，`OR 1` 时 `ans0 = ans1` 也是同样的道理。

</details>

<details>
<summary>Q3 问题</summary>

如果 m 很大（比如 10^18），但门的参数范围也相应扩大，算法是否需要修改？本题的 m=10^9 下为何只枚举到 30 位？

</details>

<details>
<summary>Q3 答案</summary>

题目中参数 t 以及 m 都不超过 10^9，10^9 < 2^30，因此 30 位（0~30）足够覆盖所有可能。如果 m 更大，只需枚举更多位（如 0~60），算法框架不变。

</details>

## 启示

<details>
<summary>启示 问题</summary>

从本题可以学到什么？

</details>

<details>
<summary>启示 答案</summary>

- **位运算独立性**：AND/OR/XOR 等按位操作天然可以让问题降维，把一个大整数问题分解为若干独立的布尔问题。
- **高位优先贪心**：在二进制权值差距极大的场景下，从高位贪心既能保证最优解，又能大幅降低复杂度。
- **模拟预处理**：分别跑 0 和 1 的"探针"，就可以快速得知每一位的选择后果，无需暴力枚举所有初始值。

</details>
